# Arjun's projects

- `projects/`: the Web Development Projects page, with a full card for each game
- `productivity/`: the Productivity page, with a full card for each tool

- `account/account.js`: optional Google sign-in, added to every page with the shared top bar. Uses the `rumblekarts` Firebase project (same as the analytics and the Back Room games). Signed-in visitors get a row in Firestore `members/{uid}` (name, email, photo, first/last visit, page count and the analytics visitor IDs of their browsers), which the analytics dashboard shows under Signed-in visitors. The Back Room games reuse a signed-in account instead of switching to an anonymous one.

- `boxed/`: Boxed, a competition math game with real AMC 10 and AIME problems: a Daily five, Practice, and live multiplayer games (Firebase, same project and Firestore rules as Hype Cycle Exchange; games are stored in `games` with `kind: "math"`). The page holds only contest names, problem numbers, official answers and a topic tag per problem (Algebra, Geometry, Number Theory, Counting & Probability); the problem text is loaded from the AoPS Wiki API while playing
- `e63334287a3deaa3/shell-crackers/`: Shell Crackers (Back Room), a first-person egg shooter (Three.js, Firebase Realtime Database rooms under `rooms/sc-…`, same project and rules as Rumble Karts). Maps are block worlds (72 × 72 m; blocks are 1 m wide and 0.5 m tall, so stairs are rows of half-metre steps) built by the functions in `MAPS` (`buildFarm`, `buildFactory`, `buildTown`) from the tools above them: `fill`/`clear`, `building` (walls, floors, windows, doors, flat or gabled roofs), `stairs`, `stairsDown`, `tunnel`, and small props. The ground is 3 m thick so tunnels fit under it, and every call is also placed turned 180° about the centre so both halves match. Bots path over a navigation graph of every spot an egg can stand. The Training range (menu button under Practice) is its own map, `buildRange` with `RANGE_MAP`, kept out of `MAPS` so it never comes up in practice or online rotation: bullseye boards at 10/20/30/45/55 m, balloons that pop and come back, and unarmed dummies (`DUMMY_ROUTES`) that strafe or patrol and respawn after being cracked. Every gun is on keys 1–5 (6 is the pistol) and T resets the stats; the number keys stay fixed there, while T is the rebindable "Reset training stats" action in the Controls panel (`keybinds.js`) and the Pistol and Swap keys work on the range too. Magazines still need reloading but never run out, yolk bombs refill, and it has no clock, no rating and no database writes; its hit, accuracy and headshot counts live only in the open tab (`Range` in the page). On touch screens it adds a button for each gun and a Reset button (`#tTrain`) to the usual touch controls. Ranked rating: Elo from each match's finishing order, multiplied by 1.25^(real opponents − 1) (×1 for one real opponent, capped at ×3; bots-only practice ×0.4; first 10 matches move faster; leaving an online match after 45 s counts as last place). Ratings are stored at `rooms/sc-ratings/players/<uid>`, which the existing rules allow; each player's own browser writes their rating, so it isn't cheat-proof.
- `e63334287a3deaa3/trivium/`: Trivium (Back Room), a trivia game: a Daily ten, Quick play by category, Survival, a 60-second Blitz, and live contests (Firebase, same project and Firestore rules as Hype Cycle Exchange and Boxed; contests are stored in `games` with `kind: "trivia"`; the host's screen grades answers and writes scores, players only write their own answers; invite links go through the home page as `#tv-<code>`). The question bank is in `e63334287a3deaa3/trivium/bank/`, one file per category; each row is `[difficulty 1–3, question, right answer, three wrong answers, fact]`. Questions get a stable ID from a hash of their text, so editing a question's wording makes it a new question. To add a category, add a file and a `<script>` tag for it in its `index.html` (and a color in `CAT_COLOR`). Keep every question and fact in your own words, and avoid facts that go out of date (current office-holders, records likely to be broken).
- `e63334287a3deaa3/showdown/`: Showdown (Back Room), no-limit Texas Hold'em for up to 8 players (Firebase Realtime Database rooms under `rooms/sd-…`, same project and rules as Rumble Karts; invite links go through the home page as `#sd-<code>`). Everything travels through each player's own node: the dealer (the player with the newest dealer number, or with none yet, whoever has been in the room longest) runs the table and publishes it as JSON in `tb`, and seals each player's hole cards to that player's key in `hc` (ECDH P-256 + AES-GCM via Web Crypto), so the database never holds readable hole cards; players write only their own action (`ac`), sit-out (`sit`), rebuy (`rb`) and chat (`ch`). The dealer's browser does see every card, so it isn't cheat-proof against a dealer with developer tools. If the dealer drops, the next player takes over from the last table it saw and refunds the hand in progress. Bots (Easy, Normal, Hard) fill empty seats and run in the dealer's browser. Play chips only; nothing is stored between sessions except practice stats in the browser.
- `e63334287a3deaa3/chromaflage/`: Chromaflage (Back Room), paint-yourself hide and seek for up to 8 players (Three.js, Firebase Realtime Database rooms under `rooms/cf-…`, same project and rules as Rumble Karts; Quick match uses `rooms/cf-pub-1` to `cf-pub-4`; invite links go through the home page as `#cf-<code>`). Hiders paint their own bodies in a paint studio (brush, an eyedropper that reads the true colour of whatever surface you click, fill, undo, glossiness) and pose to hide (crouch under tables, lie under beds, flatten, or stick to a wall with G or the Stick button and slide up, down and along it at any height, upright or sideways, until they jump to let go); seekers tag them with a blaster whose misses cost ink. Modes: Classic and Infection. Like Showdown, everything travels through each player's own node at `rooms/cf-<code>/players/<uid>`, because the shared rules expect `n, c, x, z, h, ts` there and refuse other paths (such as `events`) for new prefixes: position and pose (`y, po, fl, p`, and `wl`: 0, or 1 to 4 for the way the wall a hider is stuck to faces, with `y` its height), body (`s` shape, `sz` size, `rf` glossiness), paint (`pv` version and `pd`, the 256 × 256 body texture as a WebP data URL, or JPEG where the browser can't make WebP; about 1 KB for a plain colour and 10–20 KB for a detailed pattern, re-sent at most every 1.2 s and only when it changed, so late joiners read it straight from the node), the last shot (`sh`), squeak (`ta`) and tag claim (`tg`). The host (newest host number `he`, else whoever has been in the room longest) publishes the round as JSON in its own `rs` and checks tag claims loosely; if it leaves, the next player carries on from the last round it saw. Bodies are modelled about 1.7 units tall and drawn at `BODY` (0.64) times their size setting, so Normal is about 1.08 m; each body shape has a texture atlas where every texel knows its 3D spot on the body, so brushes paint by distance in 3D (`atlasOf`, `Paint`). The atlas layout must not change, or saved and synced paint jobs land on the wrong spots. Maps are axis-aligned boxes built by `buildFlat` (36 × 28 m, 4.4 m ceilings, eight rooms) and `buildBazaar` (a covered 54 × 54 m market hall with a 7.2 m ceiling and 24 shops) with the `Builder` helpers (`box`, `at` for turned furniture, `prop` for round things from the shared `geo()` cache, drawn as instanced meshes, `ceil` for ceilings drawn from below only so the menu's view from above looks into the rooms, `spot` for places bots hide under tables and beds, `lamp` for point lights, of which only six spread-out ones are used, three on the Fast setting) and the furniture helpers in `furn` (tables, chairs, sofas, beds, plants, lamps, boxes, curtains you can walk into, vending machines, shop mannequins). Boxes marked `soft` (cloth and leaves) block the view and the seeker bot's line of sight but not the blaster's pellets. The boxes are also the colliders, the bots' navigation grid, line of sight and the surfaces the eyedropper and bots sample; they are filed in a 2 m grid (`buildGrid`, `solidsIn`, `rayMap`) so rays and collisions stay quick. Every pattern is drawn on a canvas by the `P` painters, from a fixed seed so all players get the same map. Every room must keep a ceiling. To add a map, write a `build…` function and add it to `MAPS`. The practice seeker bot "sees" by rendering a small view of you with and without you and comparing the colours (`perceive`, delta E), so better paint really does keep you hidden; it sweeps its gaze up and down so it can spot hiders high on walls, and furniture blocks its view. Practice hider bots sometimes hang on walls or tuck under furniture. Nothing is stored online between rounds; your name, body, last paint job and settings are saved in the browser under `chroma-…`. Parties can launch it (its row in `GAMES` in `party.js`). On touch screens the page adds `touch` to `body`, and the `body.touch` rules at the end of the stylesheet place the HUD, the lobby card and the paint studio for phones held upright or sideways (keep them clear of the stick and buttons when adding HUD pieces). The lobby card and the paint studio scroll an inner box (`.lb-body`, `.st-body`) instead of the card itself, because Chrome can leave a blank patch in the 3D view under a scrolling box with a solid background.
- `e63334287a3deaa3/backrooms-1v1/`: Backrooms 1v1–4v4 (Back Room; the folder keeps its original `backrooms-1v1` name), a third-person build-fight shooter in Level 0 of the Backrooms (Three.js). Practice is you against the Entity, a bot that runs only in your browser. Online rooms hold up to 8 players split into Red and Blue (1v1 to 4v4, uneven teams like 4v3 are allowed and never filled with bots) in the Firebase Realtime Database under `rooms/br-…` (same project and rules as Rumble Karts; invite links go through the home page as `#br-<code>`). Quick match waits in `rooms/br-queue/players` and pairs two people into a `br-q…` room for a 1v1. Each player writes only their own node `players/<uid>`: `n`, `c`, `x`, `z`, `h` and `ts` always (the shared rules expect that shape), plus height, pitch, health, shield, weapon, a dead flag, the match `m` and round `rd` the position belongs to, the team picked in the lobby `t`, kills this match `k` and join time `j`; about 20 times a second during a round (15 in rooms of 5 or more) and twice a second otherwise. The host is the live player who has been in the room longest (the next in line takes over when they leave; a newcomer only starts judging who the host is once the room's players and round have loaded, so a slow phone joining mid-match can't take over and reset it) and is the only one who changes `round`: `{id, ends, seed, ns, ph, pt, to, rn, sr, sb, ro, dd, rw, mw, fm, rz}`, where `id` is the match, `ph` the phase (`lobby`, `cd` countdown, `fight`, `over`, `end`), `pt` when the phase ends, `to` the rounds to win (3, 5 or 10, host's choice), `rn` the round, `sr`/`sb` the team scores, `ro` the roster (`uid:r;uid:b`), `dd` who is out this round, `rw`/`mw` the round and match winners, `fm` a forfeit, and `rz` the host's "Randomize teams" draw (each player then moves themself). The host writes with transactions guarded on `id`, `ph` and `rn`, and keeps `ends` at the time of writing because the rules cap how far ahead it can be. Shots, builds and deaths go through `events/<push>` (deleted after 5 s): the shooter's rays pass through teammates and the shot lists only the enemies it hit; the victim applies damage only from someone on the other team of the same match, and reports its own death naming the last shooter, which gives the kill credit. A round ends when one team has nobody left: dead, or silent for 10 s (a closed tab removes its node at once). A team with nobody left in the room (disconnected, or silent for 20 s) forfeits the match. A host whose own tab has just frozen waits a moment for the queued updates before judging anyone. Players who join mid-match wait in the lobby or watch until the next one, and dead players watch a living teammate (click, or tap Next on a touch screen, for the next one). The maze is 12 × 12 cells of 4 m, 14 for 5–6 players and 16 for 7–8; Red spawns along the west edge and Blue along the east, each spawn in a cleared 3 × 3 area. Keys and mouse buttons can be changed in the Controls panel (`keybinds.js`, saved as `keybinds:backrooms-1v1`; the Change keys button under Controls in the menu, and Controls on the pause screen): move, jump, shoot / place, aim (Shift and right click), the three guns, reload, the three build pieces (two keys each), the arrow keys that look around when the mouse can't be locked, and pause (P; Esc is fixed). Clicking to watch the next teammate stays on the left mouse button, and the mouse wheel still switches guns. On touch screens it has a move stick, drag-to-look, Fire/Place, Jump, Aim, Reload and pause buttons, with the weapon and build slots as buttons along the top; while you watch, those give way to a Next button, and the lobby, pause and results screens are plain buttons that fit a phone either way up. Each browser is trusted for its own health and hits, so it isn't cheat-proof. A test hook (`window.__br`) exists only when `navigator.webdriver` is set.
- `e63334287a3deaa3/spire/`: Spire (Back Room), an obby-style parkour race up a tower stacked from random sections (Three.js, Firebase Realtime Database rooms under `rooms/tw-…`, same project and rules as Rumble Karts; Quick match uses `rooms/tw-pub-1` to `tw-pub-4`; invite links go through the home page as `#tw-<code>`; rooms hold up to 12). Everything that isn't drawing lives between the `// ==CORE==` and `// ==/CORE==` markers in the page: movement (`PHYS`, `simStep`), parts (upright boxes and cylinders, each optionally moving by `line`, `spin` or `orbit`, timed, crumbling, lethal, bouncy, a conveyor or a climbable truss), the section library (`MODS`), towers (`buildTower`), the obby (`buildObby`, `WORLDS`) and the checking bot; it has no DOM or Three.js in it, so a test can run it on its own. Physics is a fixed 120 Hz step with the player as an upright cylinder; moving parts are placed by time alone, so every player who shares the round clock sees the same tower. Each section in `MODS` is built in its own frame: it starts on the 4 × 4 pad centred at (0, 0, 8) and must end with `B.exit(H)`, its exit pad at (0, H, -8), staying inside radius 12.5 and above y = 0. Towers turn every other section 180° and may mirror any, and between sections there is a porch, a truss and a landing 4.5 higher (`RISE`), which keeps one section's high parts clear of the next one's low parts. Every section also lists a route for the bot (`B.j`, `B.w`, `B.jon`): before each jump the bot simulates it with the real `simStep` and only jumps when it lands, and it waits or hops past hazards, so a route that completes proves the section can be beaten with the real movement numbers. When adding or changing a section, run the bot over it at several difficulties, mirrored and not, and at several start times, and over whole towers (`verifyModule`, `runBot`; the page exposes them as `window.__tw` in automated browsers). Online, like Chromaflage, everything travels through each player's own node at `rooms/tw-<code>/players/<uid>`, which must always hold `n, c, x, z, h, ts`: position and animation (`y`, `a`), the round the player is in (`r`) and a finish claim (`f`, `round:milliseconds`). The host (newest host number `he`, else whoever has been in the room longest, chosen only once the room's players have loaded) publishes the round as JSON in its own `rs`: `{id, seed, ph, t0, dur, n, ez, ff, rf, fin, ne}`, where `seed` builds the tower, `t0` is the server time it starts, `ff`/`rf` mark the first finish (from then the clock runs at double speed) and `fin` is the finish order. Other players check the round before using it (`cleanRS`: finite times within a day of now, a finish list of `[uid, ms, name]`, names cleaned), so a broken host can't freeze their page. The host takes finish claims at their word, so it isn't cheat-proof. If the host leaves, the next player carries on from the last round it saw. Nothing about a round is kept online after it ends. Saved only in the browser, under `spire:` keys: name, colour, settings, the host's round options, and a profile (`spire:profile`: coins, XP, towers climbed, best times, falls, the furthest obby stage and best practice times), `spire:awarded` (the last online round that paid out, so rejoining it doesn't pay twice) and `spire:climbed` (set after the first truss climb; until then a tip shows at the foot of a truss). Keys use `keybinds.js` (`keybinds:spire`). On touch screens the page adds `touch` to `body` for a move stick, a Jump button, drag to look and pinch to zoom, with the Controls buttons hidden. Parties can launch it (its row in `GAMES` in `party.js`).
- `e63334287a3deaa3/slipstream/`: Slipstream (Back Room), a 3D open-wheel racer with a 22-car grid (Three.js, Firebase Realtime Database rooms under `rooms/ss-…`, same project and rules as Rumble Karts; invite links go through the home page as `#ss-<code>`). Bots fill every free seat; the host's browser drives them. Bot skill (`DIFF`: Easy, Normal, Hard; online races use Hard) scales corner speed, and the bots' braking, boost and lines are tuned by the `AI` constants; Hard runs close to a near-ideal lap. Track limits: going off costs nothing but time (a small "Return to the track" hint shows while off), and cutting a corner to gain time adds 1 s to the race time; each car's total penalty seconds travel online in `pn`. In automated browsers only (`navigator.webdriver`), `window.__ss` exposes the race code so a test can run bots-only races and time laps.
- `e63334287a3deaa3/party.js`: Parties (Back Room). A Party panel above the games: create a party (5-character code) or join one, up to 8 people; the person who has been in it longest is the leader, picks a multiplayer game and presses Play together, and every member's browser opens that game in a new room (`#<prefix>-p<6 random characters>`) and joins it. Back returns everyone to the party. Party invite links are `/#pt-<code>`: the home page holds them until the Back Room code is entered, then joins the party instead of opening a game. Works on the phone version too (`m/index.html` loads `party.js`, lends it its `openGame`, and sends `#pt-` invites to the party instead of Rumble Karts), and both after the home-page reveal (the home page's `reveal()` loads `party.js` from the Back Room folder and lends it `openGame` through `window.BackRoom`) and on the Back Room page opened directly (a `<script>` tag; games then open in party.js's own layer). Storage: Firebase Realtime Database, same project and rules as Rumble Karts, at `rooms/pt-<code>/players/<uid>`. The rules only let a browser write its own node and require the same fields the games write (`n`, `c`, `x`, `z`, `h`, `ts`; `x`/`z`/`h` are always 0), so the party keeps everything there: `j` (join time, which decides the leader), `pk` (game the leader picked) and `go` (the leader's latest launch: game, room, time). Nodes are removed on disconnect and ignored after 2 minutes without a heartbeat. Supported games: Shell Crackers, Rumble Karts, Slipstream, Boostball (6 max), Coil, Showdown, Backrooms 1v1–4v4 and Chromaflage. Trivium isn't supported (its contests get their code from the host's screen). party.js joins the game for each member by filling in the game's name and room boxes and pressing its own Play in room button (`#name` / `#room` / `#joinRoom`), so the games themselves weren't changed: keep those ids if you rework a game's menu. Party launches always use the member's party name, even over a name the game had saved or made up (Shell Crackers' Egg123, Rumble Karts' Driver123, Backrooms' Wanderer123, Hail Mary's random team), so everyone shows up under the name the party knows them by. Because the games save whatever is in their name box, party.js then puts the game's previously saved name back in its localStorage key (right after joining, again 3 and 15 seconds later, and when the game closes), unless the player has typed a different name since; a game that had no saved name keeps the party name. To add a game, add a row to `GAMES` in party.js (prefix, folder, room size, `nk` for the localStorage key the game saves its name under, and `ids` if its menu uses other ids).
- `e63334287a3deaa3/keybinds.js`: rebindable controls shared by the keyboard Back Room games (Backrooms 1v1–4v4, Boostball, Coil, Hail Mary, Kartwheel, Quarry, Rumble Karts, Shell Crackers, Slipstream, Starhop). Plain JavaScript, no dependencies. Each game loads it with `<script src="../keybinds.js"></script>`, lists its actions in `Keybinds.create({game, actions: [{id, label, keys: ['KeyW', 'ArrowUp']}]})` (keys are `e.code` names, so they're physical keys on any layout; mouse buttons are `Mouse0`/`Mouse1`/`Mouse2` in games that pass `mouse: true`), checks input with `KB.is(action, e.code)` and `KB.held(action, keys)` instead of comparing key codes, and opens the panel from a Controls button with `KB.open()`. Changed keys are saved only in the player's browser, under localStorage `keybinds:<game>` as `{v: 1, b: {action: [codes]}}` (only the actions that differ from the defaults; Reset to defaults removes the entry), and never go to Firebase. Esc is never rebindable. Elements with `data-kb="action"` show the current keys and update themselves. The panel takes each game's look from `--kb-*` CSS variables and the game's own button classes; the comment at the top of the file lists the options. To add it to a game, do the same, and keep text inputs (names, room codes, chat) returning before any key lookup. Touch controls don't go through key codes: each game's touch buttons feed its input directly (in Shell Crackers, Quarry and Backrooms they hold actions by id in `tAct`, which the game checks alongside `KB.held`), so they keep working whatever keys are bound, and the Change keys / Controls buttons are hidden in the touch layout (`body.touch`).

- `prompted/`: Prompted, a supplemental essay tracker for college applicants (plain JavaScript, no backend; everything is saved in the student's browser under `prompted:v1`). Students add schools with a plan and deadline, paste a supplement page to pull out each prompt with its word or character limit and whether it's optional (`parsePrompts` in the page), write drafts with a live count, save and restore versions, and start new essays from existing drafts. A reuse map groups similar prompts across schools by kind (Why us, academic interest, community, and so on). UC campuses share one application, so they're added as a single school. Update the file each August when schools publish new prompts, and keep every prompt as a summary in your own words: don't paste schools' official prompt text into this repo, even though it's posted publicly. No ads on this page.
