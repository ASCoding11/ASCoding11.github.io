# Arjun's projects

Personal site hosted with GitHub Pages.

- `index.html`: the home page, with links to the Web Development Projects and Productivity pages
- `projects/`: the Web Development Projects page, with a full card for each game
- `productivity/`: the Productivity page, with a full card for each tool
- `account/account.js`: optional Google sign-in, added to every page with the shared top bar. Uses the `rumblekarts` Firebase project (same as the analytics and the Back Room games). Signed-in visitors get a row in Firestore `members/{uid}` (name, email, photo, first/last visit, page count and the analytics visitor IDs of their browsers), which the analytics dashboard shows under Signed-in visitors. The Back Room games reuse a signed-in account instead of switching to an anonymous one.
- `site.css`: styles shared by the home, Web Development Projects and Productivity pages
- `hype-cycle-exchange/`: Hype Cycle Exchange, a live classroom stock-market game (Firebase)
- `boxed/`: Boxed, a competition math game with real AMC 10 and AIME problems: a Daily five, Practice, and live multiplayer games (Firebase, same project and Firestore rules as Hype Cycle Exchange; games are stored in `games` with `kind: "math"`). The page holds only contest names, problem numbers, official answers and a topic tag per problem (Algebra, Geometry, Number Theory, Counting & Probability); the problem text is loaded from the AoPS Wiki API while playing
- `e63334287a3deaa3/shell-crackers/`: Shell Crackers (Back Room), a first-person egg shooter (Three.js, Firebase Realtime Database rooms under `rooms/sc-…`, same project and rules as Rumble Karts). Maps are block worlds (72 × 72 m; blocks are 1 m wide and 0.5 m tall, so stairs are rows of half-metre steps) built by the functions in `MAPS` (`buildFarm`, `buildFactory`, `buildTown`) from the tools above them: `fill`/`clear`, `building` (walls, floors, windows, doors, flat or gabled roofs), `stairs`, `stairsDown`, `tunnel`, and small props. The ground is 3 m thick so tunnels fit under it, and every call is also placed turned 180° about the centre so both halves match. Bots path over a navigation graph of every spot an egg can stand. Ranked rating: Elo from each match's finishing order, multiplied by 1.25^(real opponents − 1) (×1 for one real opponent, capped at ×3; bots-only practice ×0.4; first 10 matches move faster; leaving an online match after 45 s counts as last place). Ratings are stored at `rooms/sc-ratings/players/<uid>`, which the existing rules allow; each player's own browser writes their rating, so it isn't cheat-proof.
- `e63334287a3deaa3/trivium/`: Trivium (Back Room), a trivia game: a Daily ten, Quick play by category, Survival, a 60-second Blitz, and live contests (Firebase, same project and Firestore rules as Hype Cycle Exchange and Boxed; contests are stored in `games` with `kind: "trivia"`; the host's screen grades answers and writes scores, players only write their own answers; invite links go through the home page as `#tv-<code>`). The question bank is in `e63334287a3deaa3/trivium/bank/`, one file per category; each row is `[difficulty 1–3, question, right answer, three wrong answers, fact]`. Questions get a stable ID from a hash of their text, so editing a question's wording makes it a new question. To add a category, add a file and a `<script>` tag for it in its `index.html` (and a color in `CAT_COLOR`). Keep every question and fact in your own words, and avoid facts that go out of date (current office-holders, records likely to be broken).
- `e63334287a3deaa3/showdown/`: Showdown (Back Room), no-limit Texas Hold'em for up to 8 players (Firebase Realtime Database rooms under `rooms/sd-…`, same project and rules as Rumble Karts; invite links go through the home page as `#sd-<code>`). Everything travels through each player's own node: the dealer (the player with the newest dealer number, or with none yet, whoever has been in the room longest) runs the table and publishes it as JSON in `tb`, and seals each player's hole cards to that player's key in `hc` (ECDH P-256 + AES-GCM via Web Crypto), so the database never holds readable hole cards; players write only their own action (`ac`), sit-out (`sit`), rebuy (`rb`) and chat (`ch`). The dealer's browser does see every card, so it isn't cheat-proof against a dealer with developer tools. If the dealer drops, the next player takes over from the last table it saw and refunds the hand in progress. Bots (Easy, Normal, Hard) fill empty seats and run in the dealer's browser. Play chips only; nothing is stored between sessions except practice stats in the browser.
- `e63334287a3deaa3/backrooms-1v1/`: Backrooms 1v1–4v4 (Back Room; the folder keeps its original `backrooms-1v1` name), a third-person build-fight shooter in Level 0 of the Backrooms (Three.js). Practice is you against the Entity, a bot that runs only in your browser. Online rooms hold up to 8 players split into Red and Blue (1v1 to 4v4, uneven teams like 4v3 are allowed and never filled with bots) in the Firebase Realtime Database under `rooms/br-…` (same project and rules as Rumble Karts; invite links go through the home page as `#br-<code>`). Quick match waits in `rooms/br-queue/players` and pairs two people into a `br-q…` room for a 1v1. Each player writes only their own node `players/<uid>`: `n`, `c`, `x`, `z`, `h` and `ts` always (the shared rules expect that shape), plus height, pitch, health, shield, weapon, a dead flag, the match `m` and round `rd` the position belongs to, the team picked in the lobby `t`, kills this match `k` and join time `j`; about 20 times a second during a round (15 in rooms of 5 or more) and twice a second otherwise. The host is the live player who has been in the room longest (the next in line takes over when they leave) and is the only one who changes `round`: `{id, ends, seed, ns, ph, pt, to, rn, sr, sb, ro, dd, rw, mw, fm, rz}`, where `id` is the match, `ph` the phase (`lobby`, `cd` countdown, `fight`, `over`, `end`), `pt` when the phase ends, `to` the rounds to win (3, 5 or 10, host's choice), `rn` the round, `sr`/`sb` the team scores, `ro` the roster (`uid:r;uid:b`), `dd` who is out this round, `rw`/`mw` the round and match winners, `fm` a forfeit, and `rz` the host's "Randomize teams" draw (each player then moves themself). The host writes with transactions guarded on `id`, `ph` and `rn`, and keeps `ends` at the time of writing because the rules cap how far ahead it can be. Shots, builds and deaths go through `events/<push>` (deleted after 5 s): the shooter's rays pass through teammates and the shot lists only the enemies it hit; the victim applies damage only from someone on the other team of the same match, and reports its own death naming the last shooter, which gives the kill credit. A round ends when one team has nobody left: dead, or silent for 10 s (a closed tab removes its node at once). A team with nobody left in the room (disconnected, or silent for 20 s) forfeits the match. A host whose own tab has just frozen waits a moment for the queued updates before judging anyone. Players who join mid-match wait in the lobby or watch until the next one, and dead players watch a living teammate (click for the next). The maze is 12 × 12 cells of 4 m, 14 for 5–6 players and 16 for 7–8; Red spawns along the west edge and Blue along the east, each spawn in a cleared 3 × 3 area. Each browser is trusted for its own health and hits, so it isn't cheat-proof. A test hook (`window.__br`) exists only when `navigator.webdriver` is set.
- `docket/`: Docket, a study planner for Canvas students (plain JavaScript, no backend; everything is saved in the student's browser). It imports assignments three ways: a bookmarklet that reads the Canvas API from the student's logged-in Canvas tab and hands the data to Docket in the URL hash (its source is the `bmSrc` block in the page), the Canvas calendar feed / any `.ics` or Google Calendar `.zip` export, or pasted text from a Canvas assignments page. It estimates time and difficulty per assignment, then schedules study sessions around calendar events and the student's activities. No ads on this page.
- `prompted/`: Prompted, a supplemental essay tracker for college applicants (plain JavaScript, no backend; everything is saved in the student's browser under `prompted:v1`). Students add schools with a plan and deadline, paste a supplement page to pull out each prompt with its word or character limit and whether it's optional (`parsePrompts` in the page), write drafts with a live count, save and restore versions, and start new essays from existing drafts. A reuse map groups similar prompts across schools by kind (Why us, academic interest, community, and so on). Backups download as JSON; all drafts download as one .txt. `prompted/schools.js` is the school library: the U.S. News 2027 top 50 national universities with their 2026–27 supplement prompts (as short summaries in our own words, with real limits), choose-N sets, college- or program-specific prompts keyed to the student's intended major, application plans and deadlines. UC campuses share one application, so they're added as a single school. Update the file each August when schools publish new prompts, and keep every prompt as a summary in your own words: don't paste schools' official prompt text into this repo, even though it's posted publicly. No ads on this page.

Ads: Google AdSense runs only on the game pages. The home page carries just the `google-adsense-account` meta tag, which verifies the site with AdSense without loading any ads. `ads.txt` (site root) and `privacy.html` are required by AdSense. Hype Cycle Exchange uses automatic ads; the other games show banners only on their menu and results screens, switched on by pasting a display ad unit ID into `AD_SLOT` near the top of each game's script.

The game's secret results file (`rounds.json`) is intentionally **not** in this repository. Keep it on your own computer and choose it when you host a game.
