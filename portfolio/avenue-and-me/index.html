Avenue & Me. Find out if it’s mutual.

A matching site for the Avenues high school, grades 9–12. Each student privately picks up to three people they’d like to connect with. A match appears only when two people pick each other. A one-sided pick is never shown to anyone.

How it works

  1. Each student gets a private code by email. A mail-merge script I wrote in Google Apps Script sends every student their 8-character code and a one-tap login link.
  2. They log in and pick up to three people from a searchable list of the high school, optionally with a note of up to 140 characters.
  3. Mutual picks become matches. Both people get an email saying they have a new match, without naming who. The note is revealed only to the person picked, and only once it’s mutual.

Privacy enforced by the database, not the page

A site like this only works if students trust that a one-sided pick stays secret. So the guarantees live in Firestore security rules on the server, where no one can get around them by editing the page.

No one can read who picked whom

A match is detected by asking to read a single document that the rules only open when both picks exist. A one-sided pick returns the same “denied” as no pick at all.

Nothing can be listed

A student’s picks live at a path containing their own code, and no collection students can reach is listable. You can only read what you can already name.

No fishing

Picks can’t be edited and can only be removed seven days after they’re made, so no one can pick and unpick repeatedly to test whether someone picked them.

Notes stay sealed

A note is copied to notes/{them}_{you}, readable only by the person picked and only after a match. To prove who is reading, the browser links an anonymous sign-in to the student’s code.

Built with

  • Frontend plain HTML/CSS/JS, no build step
  • Hosting Cloudflare Pages, deploys on every push
  • Data Firebase Firestore + security rules
  • Auth Firebase Auth: code, username/password, anonymous
  • Email Google Apps Script mail merge
  • Admin private dashboard: stats, roster upload, moderation

What I’d improve next

Login codes are currently each student’s school ID, which made rollout easy because every student already has one. The trade-off is that anyone who knows someone’s ID could log in as them. The next step is issuing random codes and moving everyone to username-and-password accounts.
